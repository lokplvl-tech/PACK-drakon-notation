# Bounded Context: Нотация ДРАКОН

---

## Domain Name

**Нотация ДРАКОН**

(English: DRAKON Notation)

---

## Object of Description

**Схема ДРАКОН как формальный визуальный объект, подчинённый жёстким правилам построения** - объект инженерного описания.

| Object IS | Object IS NOT |
|-----------|---------------|
| Формальная структура с проверяемыми правилами (шампур, силуэт, запреты) | Произвольная блок-схема «для наглядности» |
| Рендер уже существующей логики метода, либо источник для генерации кода | Домен, к которому применяется схема |
| Носитель узнаваемых нарушений (failure modes) с именами из первоисточника | Учебник по конкретному редактору |

## Scope (What's In)

| Element | Description | Example |
|---------|-------------|---------|
| **Строительные блоки** | Иконы/макроиконы: Заголовок, Действие, Вопрос, Имя ветки, Адрес, Вставка, Полка, Конец | Икона «Вопрос» для развилки |
| **Формальные конструкции** | Шампур-блок, примитив, силуэт | Силуэт из именованных веток для сложного алгоритма |
| **Жёсткие правила** | Правило шампура, правило главного маршрута, «чем правее - тем хуже», запреты (пересечения, обрывы, сиамские близнецы) | Успешный путь - крайняя левая вертикаль |
| **Приёмы** | Рокировка, «разрежь великана» + Вставка, три царских вопроса, трёхэтапный метод познания, диосцена | Три царских вопроса как вход в «шапку» силуэта |
| **Перевод метода в схему** | Соответствие между позициями потока (`E.18`) и элементами языка | Ветка силуэта = именованная позиция метода |
| **Инструментальная связка** | Отрисовка (DrakonHub) и генерация кода (проверено для JavaScript) | Формульная позиция метода → JavaScript для САПР |

## Non-Goals (What's Out)

| Excluded | Reason | Where It Belongs |
|----------|--------|------------------|
| Логика конкретного метода (что домен на самом деле делает) | Это содержание предметного Pack, схема - только его рендер | `PACK-furniture-engineering`, `PACK-jet-lighter-engineering` и др. |
| Интерфейс конкретного редактора | Инструмент меняется, правила языка - нет | Документация инструмента |
| Генерация кода как самоцель | Оправдана только там, где код - реальный продукт визуального проектирования | Решается в предметном Pack/РП (см. `DRK.D.003`) |

## Truth Criteria

Утверждения в этом Pack считаются обоснованными, если:

| Criterion | Test |
|----------|------|
| **Опора на первоисточник** | Правило прослеживается до книги/рукописи Паронджанова, не до вторичного пересказа |
| **Проверяемое нарушение** | Каждый failure mode - названная в источнике запрещённая конструкция, не произвольная стилистическая придирка |
| **Соответствие структуре метода** | Перевод в схему проверяется сверкой с исходной таблицей позиций (`E.18`) - расхождение недопустимо |
| **SoTA + критерий пересмотра** | Для утверждений об инструментах (не о языке) - отдельная пометка, что это состояние инструмента на 2026 год, не правило языка |

**Запрещено**:
- Смешивать правило языка (неизменное) с возможностью конкретного редактора (меняется)
- Утверждать нарушение без ссылки на конкретный запрет из источника
